# 单词本：开发目标与技术方案

版本：1.0 · 状态：第一版实现依据

## 1. 项目目标

为个人开发一个启动方便、录入流畅、完全离线的 Windows 单词本。使用者手动输入英文单词、词性与中文释义，程序保存到 SQLite；复习时可以揭晓答案、标记已记下、设置重点，并查看自行录入的关联词。

核心目标是减少操作步骤：横向连续输入、键盘完成常用动作、原地纠错、即时保存状态。第一版交付源码以及包含 EXE 的完整程序文件夹，直接双击运行，无需另装 Python。

第一版不提供联网词典、自动翻译、账号、云同步、发音、导入导出或间隔重复算法。

## 2. 环境与技术路线

| 项目 | 方案 |
| --- | --- |
| 目标平台 | 本机 Windows 64 位，兼容 Windows 10/11 桌面使用方式 |
| 开发语言 | Python 3.12 |
| 桌面界面 | PySide6 / Qt Widgets |
| 列表控件 | QTableView + QAbstractTableModel + QStyledItemDelegate |
| 数据库 | Python 标准库 sqlite3，单个 SQLite 数据库文件 |
| 样式 | 本地深色样式、Qt 绘制的矢量图标、系统中文字体 |
| 测试 | pytest、pytest-qt / QtTest、临时 SQLite 数据库 |
| 打包 | PyInstaller，onedir + windowed，无控制台窗口 |
| 依赖管理 | 项目 .venv、pyproject.toml、实际安装版本锁定文件 |

Qt 的表格模型和编辑代理用于实现多行释义、隐藏遮罩、图标操作与就地编辑。SQLite 无需数据库服务，适合个人本地持久化。安装开发依赖需要联网，成品运行不需要网络；图标、样式等运行资源不从远程加载。

## 3. 使用对象与概念

- **主词**：主列表中的一个完整词条，具有名称、释义、关联词、重点和记忆状态。
- **释义**：一组“词性 + 翻译”。同一个词可以有多组释义，翻译可以包含换行。
- **关联词**：主词的附属内容，可以有多个，每个关联词也支持多组释义。它不单独进入主列表，不具有独立重点和记忆状态，也不会自动建立双向关联。
- **重点**：主词的布尔属性，亮星代表重点，灰星代表非重点。
- **已记下**：主词的布尔属性，决定其所属的待记/已记下列表。

## 4. 主窗口设计

窗口采用深色主题，上方为复习列表，下方为固定位置的录入区域。初始尺寸约 1040×820，最小尺寸 860×640；支持窗口缩放和 Windows 显示缩放。内容较多时列表与录入内容分别滚动，底部操作栏始终可见。

系统窗口标题为 `kkMemorizeVocabulary`。页面不设置“单词本”大标题和独立标题栏，顶部直接显示筛选栏，右上角提供全局隐藏开关，将空间留给列表。

### 4.1 上方列表

列顺序：**无标题的窄星标列 | 单词 | 词性 | 翻译 | 操作**。

- 星标列仅容纳小星图标；词性列较窄；翻译列使用剩余空间。
- 顶部提供“待记、全部、已记下”筛选和主词数量；默认待记，按新增顺序正序，最新词条位于最下方。修改已有词不改变排序。
- 新增主词保存成功后，主词及关联词默认展开，列表自动选中该主词并滚动到底部；当前在已记下视图时，自动切换待记视图以展示新词。
- 单词和翻译不采用上下堆叠布局。每条释义的词性与翻译顶端对齐，翻译按显式换行和列宽自动折行。
- 关联词在单词列缩进，其词性、翻译与主词采用同一列对齐；只有主词首行显示星标和操作。
- 新启动时所有词条默认隐藏，展开状态仅在内存中保留，不写数据库。
- 右上角“全局隐藏”开关一次改变所有词条的展开状态，包含当前筛选未显示的词条。打开时全部隐藏，关闭时全部展开；之后仍可逐词操作，新保存的主词仍默认展开。该开关不持久化，每次启动默认开启。

### 4.2 遮罩与复习

- 隐藏状态下，每个主词只显示一条浅灰色圆角长条遮罩，跨越词性和翻译两列；关联词整体不显示，不为各条释义另画灰条。
- 单击遮罩，一起显示主词全部词性、翻译及全部关联词。
- 非编辑状态下，Ctrl + 单击任一已显示翻译，隐藏所属主词的整组答案。
- 不设置“查看翻译”“收起翻译”文字按钮。

### 4.3 列表操作

| 状态 | 图标操作 |
| --- | --- |
| 待记 | 圆圈：标记已记下；铅笔：编辑整组；垃圾桶：删除 |
| 已记下 | 红色横杠：恢复待记；铅笔：编辑整组；垃圾桶：删除 |

所有图标带鼠标悬停说明和无障碍名称。星标点击后立即保存，非重点显示同形灰星。关联词不显示这些操作。

标记已记下后，词条从待记视图移出，提供最近一次标记的撤销入口。删除主词前确认，并级联删除其全部释义与附属关联词。

### 4.4 就地编辑与整组编辑

- 双击主词/关联词名称：显示单行编辑器。
- 双击词性：显示统一的词性选择框。
- 双击翻译：显示多行编辑器。
- 就地编辑使用当前配置的保存快捷键提交，离开编辑器时也提交；Esc 取消。无效内容或写入失败保留编辑内容并提示，不能静默丢弃。
- 铅笔图标把词条完整载入底部，支持新增/移除关联词和释义；提供“保存修改”和“取消”。
- 就地编辑与底部整组编辑互斥。开始另一种编辑前先处理已有编辑；不能让旧表单覆盖更新后的词条。

## 5. 录入表单

每个词的首行依次为 **单词输入框 → 词性下拉框 → 翻译多行输入框**，追加释义只增加词性与翻译，不重复单词输入框。

主词下方可添加多个关联词，关联词使用相同的横向录入结构。每个词始终至少保留一组释义输入框，初始词性未选择。

- 全局“新增关联词”“移除末项关联词”按钮始终显示当前快捷键。
- 各词有“新增释义”“移除末项释义”按钮，只有焦点所属的词显示这两个按钮的快捷键。
- 新增关联词后聚焦新单词框；新增释义后聚焦新词性框。
- 移除已有内容的关联词或释义时确认，默认焦点在确认按钮，空格确认、Esc 取消；空白项直接移除。
- 每个词仅剩一条释义时，移除释义操作不执行；没有关联词时，移除关联词操作不执行。
- 底部同一行从左到右放“快捷键设置”“新增关联词”和“移除末项”，右侧放取消、小星标和保存；新增关联词不用加号前缀，全局操作按钮继续显示从数据库读取的快捷键。
- 新建词条默认重点点亮，保存成功后清空表单、恢复重点默认值、焦点回到主词框。
- 编辑已有词条时读取原重点值，取消时不修改数据库。
- Tab 正向移动、Shift+Tab 反向移动；翻译输入框 Enter 换行；星标获得焦点后可按空格切换。Ctrl+A 保留文字全选。
- 未保存输入切换到其他词条或关闭窗口时，提供保存/放弃/取消。

## 6. 词性控件

| 数字 | 显示词性 | 含义 |
| --- | --- | --- |
| 1 | n. | 名词 |
| 2 | v. | 动词 |
| 3 | adj. | 形容词 |
| 4 | adv. | 副词 |
| 5 | prep. | 介词 |
| 6 | pron. | 代词 |
| 7 | conj. | 连词 |
| 8 | interj. | 感叹词 |
| 9 | 其他 | 其他 |

收起状态仅显示词性，不显示数字。获得焦点时，直接按 1–9 立即切换当前词性，无需展开，切换后焦点保留。空格或鼠标打开下拉框，选项左侧显示数字并显示中文含义；展开后数字键也可选择并关闭下拉框。方向键选择、Enter 确认、Esc 取消本次下拉选择。

该控件统一用于主词、关联词和列表就地编辑。数据库仅保存词性代码，不把快捷数字混入词性或翻译文本。

## 7. 快捷键与设置窗口

| 设置键 | 操作 | 默认组合 |
| --- | --- | --- |
| add_related | 新增关联词 | Ctrl+N |
| remove_related | 移除最后一个关联词 | Ctrl+M |
| add_sense | 新增当前词的释义 | Ctrl+J |
| remove_sense | 移除当前词的末项释义 | Ctrl+K |
| save | 保存 | Ctrl+Enter |
| important | 切换录入主词的重点 | Ctrl+I |

### 7.1 作用域与提示

- 释义操作只作用于当前焦点所在的词，没有词目标时不执行。
- 焦点在词的名称、词性、翻译或其释义按钮上，均视为该词获得焦点；其他词的释义按钮不显示快捷键。
- 全局操作按钮始终显示配置中的按键，不把默认字符串写死在按钮上。
- 保存快捷键在列表编辑期间优先提交当前单元格，否则保存底部整组表单。
- 保存草稿后若立即进入列表就地编辑，延迟滚动不得打断当前编辑器。
- 重点快捷键只切换底部当前录入主词，不能用于关联词。
- 设置窗口打开时保留表单内容，关闭后恢复之前输入位置。捕获组合键期间暂停业务快捷键。

### 7.2 设置持久化和即时更新

设置窗口显示六项操作、当前快捷键、修改入口、恢复默认和完成按钮。点击修改后捕获新的单段组合，Esc 取消。

严格遵循以下顺序：

1. 校验组合键：需要 Ctrl 或 Alt 修饰，不允许重复，不占用 Ctrl+A/C/V/X/Z/Y、固定导航键及 Alt+F4。
2. 在事务内更新 SQLite，提交成功。
3. 从数据库重新读取完整快捷键配置。
4. 替换运行中的快捷键绑定，更新按钮文字和悬停提示，立即生效。

写库失败时不修改旧绑定；应用新绑定失败时恢复旧配置和绑定。启动时读取数据库；首次运行只为缺失设置写入默认值，不覆盖用户已有配置。

词性数字映射、Tab/Shift+Tab、Enter 换行、空格操作和 Ctrl+单击隐藏不在第一版可配置范围内。

## 8. 数据结构与一致性

### 8.1 位置与生命周期

- 默认数据库：`%LOCALAPPDATA%\kkMemorizeVocabulary\vocabulary.sqlite3`。
- 日志与数据库位于同一用户数据目录，程序更新不覆盖用户数据。
- 支持 `--data-dir <目录>`，测试和开发使用隔离目录。
- 使用 `PRAGMA user_version` 记录数据库版本，第一版为 1；拒绝打开无法理解的更高版本数据库。
- 启用外键及 WAL，所有聚合保存和删除均使用事务。

### 8.2 表设计

| 表 | 主要字段与约束 |
| --- | --- |
| words | id、text、normalized_text（唯一）、important、learned、created_at、updated_at |
| related_words | id、word_id（级联外键）、text、position |
| senses | id、word_id 或 related_id（二选一所属）、pos、translation、position |
| settings | key（主键）、value（规范化快捷键字符串） |

主词名称用 `strip().casefold()` 生成唯一检查值，保留用户原始大小写用于显示。词性与翻译分字段存储，翻译保留内部换行。顺序字段保持用户的释义和关联词排列。

### 8.3 保存与校验

- 主词必须有名称和至少一条完整释义，每个保存的关联词同样如此。
- 完全空白的额外行可忽略；有部分内容但未填完整时阻止保存并保留输入。
- 重复主词不创建、不覆盖，保留当前表单并提供定位已有词的入口；定位时切换全部列表、选中并滚动到目标。
- 关联词不受主词唯一性约束，不自动合并或建立双向关系。
- 整组编辑保持主词 ID，不把旧表单中的记忆状态覆盖到最新状态。
- 只有事务成功后更新界面；出错时保留输入与原持久化内容。

## 9. 模块边界与内部接口

- `domain`：WordEntry、RelatedWord、Sense、词性和默认快捷键定义，输入校验。
- `storage`：数据库初始化、读取聚合、保存聚合、删除、状态变更、快捷键读取与写入；负责事务与 SQL。
- `shortcuts`：规范化与校验、按作用域分发、设置生效和失败恢复。
- `widgets`：词性选择框、释义输入行、主词/关联词输入组、确认窗口、图标绘制。
- `table`：视图行投影、自定义绘制、行高与换行、遮罩、点击/双击分发、就地编辑。
- `window`：筛选、表单编辑状态、焦点目标、设置窗口、提示与撤销。
- `app`：命令行入口、用户数据目录、日志、主题、程序生命周期。

数据通过 Python 数据对象在层间传递，UI 不拼接 SQL；所有数据值使用 SQL 参数绑定。没有对外网络 API。

## 11. 测试与验收

### 自动化测试

- 多词性、多行翻译、多个关联词的保存、更新、关闭重开。
- 重复主词检查，关联词同名允许，删除级联、事务失败回滚。
- 词性收起/展开显示、数字选择、空格打开、Esc 取消。
- 焦点对应的释义快捷键和动态提示，Tab/Shift+Tab、Enter 换行、星标空格切换。
- 空白与有内容项的移除确认、最后一项释义保护。
- 数据库提交先于绑定生效；新键有效旧键失效、冲突拒绝、失败保持原设置、重启保留。
- 遮罩数量、整组展开/隐藏、正确单元格编辑、取消和持久化。

### 实际窗口与成品检查

- 深色外观、长词、多行翻译、多关联词、缩放窗口不重叠。
- 检查 Windows 125% 和 150% 缩放下的文字、图标、输入及点击区域。
- 中文输入法不被数字选择和保存快捷键误干扰。
- EXE 无控制台、无需 Python、离线启动可用，退出重启后数据与设置保留。
- 测试使用临时数据库，不把演示词写入正式用户数据库。

## 12. 交付与维护

交付源码、依赖锁定文件、自动化测试、打包配置、使用说明、EXE 完整文件夹及 ZIP。发布目录与开发虚拟环境、测试数据库分离。

备份时先退出程序，再复制用户数据目录中的数据库文件；更新时替换程序文件夹，保留用户数据目录。后续新增功能先更新本文档和数据版本策略，再修改实现。

打包使用仅含项目虚拟环境和 Windows 目录的依赖搜索路径，避免从其他开发工具收集不兼容的 ICU DLL。Qt 使用 Windows 自带的 ICU 接口，不随包附带第三方同名 ICU 或 API-set 替代文件。发布检查必须验证包内 Python 模块与当前源码一致，并检查这些错误依赖没有混入；同时实际运行 EXE 验证首次保存和重启恢复。
